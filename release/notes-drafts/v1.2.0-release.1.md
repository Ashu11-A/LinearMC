From this release on, every LinearMC build has the same features: the Horizon plugin for Paper, Folia and CanvasMC now does everything the Folia and CanvasMC forks do. It also fixes three data-safety bugs. One could regenerate existing worlds, and the other two lost writes or skipped conversions. If you run the v1.1.4 Horizon plugin on an existing world, upgrade.

## Data-safety fixes

- Horizon regenerated existing worlds. On a world that already had `.mca` regions, switching to LINEAR made the server think those regions were missing and generate them again. `.linear` regions had the same problem after switching back to ANVIL. The host checked whether the region file existed before LinearMC had a chance to look for it in another format. Now every build looks for a region in all three formats (`.mca`, `.linear`, `.b_linear`) first, and a region that is being converted keeps serving its old file. We reproduced the bug with the `v1.1.4-release.1` jar.
- A live convert could delete an `.mca` file the server still had open, and every later write to that region was lost. Every build now records each `.mca` file the server opens and never deletes one of those during a live convert. They are reported as `SKIPPED` and kept. If a region is converted while the server is opening it, the server opens the new file.
- On the Folia fork, `/linear convert --execute` stayed at `Working 0/0` and converted nothing. It now runs.
- On the CanvasMC fork, `/linear convert --to-blinear` wrote `.linear`. The CanvasMC fork now uses the same convert runner as Folia and Horizon, so `--to-blinear` writes `.b_linear` everywhere.

## What the Horizon plugin gained

- Existing worlds are converted automatically at startup, before plugins load.
- The default format is LINEAR, as on the forks.
- Format and compression level can be set per world under `worlds:` in `plugins/LinearMC/config.yml`.
- `/save-all` writes pending Linear data to disk, and stopping the server writes everything changed since the last world save.
- Flushing no longer blocks region lookups ("flush-unlock"), as on the forks.
- `io.linearmc.horizon.event.LinearRegionFlushCompletedEvent` fires after each flush.
- `/linearstats` shows the cache and oversize counters, and oversized chunks are rejected the same way as on the forks.
- A broken region symlink stops the server instead of making the world look empty.
- `/linear convert` covers `region/`, `entities/` and `poi/`, and honors `-Dlinearmc.compression-level`.

## Upgrading

- Horizon on an existing world: with LINEAR as the new default, existing regions convert on the first boot. Take a backup first and keep about 2.5× the world size free on disk. To go back to `.mca` before removing the plugin, run `/linear convert <world> --to-mca --execute` for each world; the boot log repeats this hint. To stay on Anvil, set `format: ANVIL` in `plugins/LinearMC/config.yml`.
- Forks: nothing changes for worlds that are already Linear.
- Live convert: `.mca` regions the server has opened since startup are kept and reported as `SKIPPED`. To convert them, restart the server and run the convert again before those regions load.
