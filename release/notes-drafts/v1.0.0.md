LinearMC stores Minecraft regions in the Linear format and can cut world size on disk by up to 45%. This first release ships Folia and Canvas server builds plus the Horizon plugin for Paper-style servers. Gameplay does not change.

## Before you start

- You need Java 25 (`java -version` shows it).
- Pick the jar for your server type from the assets below. There is nothing to compile.
- Back up your worlds before converting, and keep that backup until players confirm everything is intact.

## Added

- Linear region files. Each 32×32 chunk region is one compressed `.linear` file instead of many small padded sectors. Chunk access uses LZ4, the whole region is compressed with zstd on flush, every file carries checksums, and saves go through a temp file that is forced to disk and then moved into place.
- Linear is the default. New worlds write `region-format.format: LINEAR` at compression level 6. Worlds pinned to `ANVIL` keep working as before.
- Reads look for `.mca` first and then `.linear`, whatever format is configured, so old files keep loading from the first boot.
- Startup conversion. On boot, before any plugin code runs, leftover `.mca` files in Linear worlds are converted to level-6 `.linear`. Worlds set explicitly to ANVIL are never converted.
- The conversion pipeline runs CONVERT, VALIDATE and DELETE for each file, in parallel on a bounded pool, and never deletes a file it has not validated. A failed file is retried up to 3 times. If it still fails, the server enters protection mode and halts for inspection rather than risk the data.
- `/linearstats` shows live compression figures per folder (region, poi and entities for each world), in human units, with a dirty bar and TOTALS. On the Horizon plugin the command is `/linear stats`.
- `/linear convert` queues a conversion for one world, in either direction (`--to-linear` or `--to-mca`). It is a dry run unless you pass `--execute`, so going back to Anvil needs no script.
- `/linear queue` lists background conversion jobs and can show status, pause, resume, cancel or clear them by id. `/linear help` lists the commands in game.
- `LinearStats` Paper API for plugins: a `FolderSnapshot` delegate and a call site for the flush-completed event bridge.
- Horizon plugin 1.0.0 brings Linear to Paper-style servers without rebuilding the server: put two jars in `plugins/` and start with `-Dlinearmc.format=LINEAR`. Without the flag it stays in Anvil mode.
- Unloads, explicit saves and shutdown all drain through `flushAllDirty`/`evictAll`, so files still dirty at stop are written as `.linear`.
- Periodic flushes are submitted to a shared bounded pool and nothing waits on them, so a file flush never stalls chunk generation. Forced and stop drains still wait for completion, and a clean shutdown loses nothing.
- Flushes run oldest-dirty first, paced by `flush-frequency`, with an opportunistic drain on `markDirty`. The zstd writer uses `setWorkers`/`setLong` and the reader uses `setLongMax(27)`.
- Settings: `region-format.format`, `compression-level`, `crash-on-broken-symlink`, `flush-frequency` and `flush-max-threads`. The JVM flags `-Dlinearmc.format` and `-Dlinearmc.compression-level` override the config files.
- New documentation: README, operator manual, concepts, commands, observability, performance notes, FAQ and architecture pages.

## Fixed

- Reads no longer miss a region when files in both formats exist for it.
- A broken symlink now halts the server, so the chunks behind it are not regenerated and written over.
- `.mca` and `.linear` file name matching is stricter and no longer matches unrelated files.
- Dirty files no longer wait for a manual `save-all flush`. They are written within about `flush-frequency`.
- The flush picks the file that has gone longest without a flush, so the stalest data is written next.
- The level column in the stats panel resolves by name and then by dimension identifier instead of showing `?`, and it no longer throws.
