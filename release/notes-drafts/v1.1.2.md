This release brings the Horizon plugin level with the forks. On the Folia and Canvas forks it replaces `v1.1.1` directly, with the same bytes on disk, config defaults and behavior. The Horizon plugin gets its first update since `v1.0.0` and is now a single jar for every supported Minecraft line.

## Breaking changes

- The Horizon asset was renamed from `linearmc-horizon-26.3-<proj>.jar` to `linearmc-horizon-1.0.0-1.1.2.jar`. It is one jar that loads on 26.1 through 26.3. Update any download script that uses the old name.

## Changes

- Four Horizon settings were read but never used. `flush-max-threads`, `flush-frequency` (the coordinator's age check; the heartbeat already followed the file), `compression-workers` and `long-distance-matching` now register the same core hooks as on Canvas, with the documented defaults of 1, 10, 0 and 0.
- Horizon honors `crash-on-broken-symlink: false`, which boots without the symlink guard for forensic work. The default `true` still refuses broken symlinks. The flush-completion listener does nothing on Horizon, because this plugin has no event bridge.
- The plugin version follows the project tag. On tag builds, the Gradle project version, `paper-plugin.yml` and `horizon.plugin.json` are stamped with `LINEARMC_PROJECT_VERSION`; local builds keep `1.0.0-SNAPSHOT`.
- One jar for all Minecraft lines. It is built against the oldest bundle (`26.1.2.build.74-stable`, `api-version: 26.1`). The six places where it touches NMS are identical in the 26.1 to 26.3 bundles, and it only uses API that already exists in the oldest one, so there is no need for a jar per version.
- CI builds the plugin and runs its unit tests against every pinned bundle (26.1.2, 26.2, 26.3), including a reflection check that every mixin selector target exists in that bundle's NMS.
- Parity rule: any change to commands, config keys or `linear$` hooks must land on every server type in the same change (see `CONTRIBUTING.md`). Gate `4b` in `scripts/preflight.sh` checks the config keys and the hooks.

## Fixes

- On Horizon, `flush-max-threads`, `compression-workers`, `long-distance-matching` and the `flush-frequency` age check ignored `config.yml`, so the coordinator and codec ran on the shipped defaults. They now read it.
- Horizon no longer ignores `crash-on-broken-symlink: false`.
- Horizon failed on live servers: the redirect on the exists check now tolerates hosts that lack the Moonrise bridge method (`require = 0`). Before, the whole mixin was rejected and worlds stayed `.mca`. The same jar was tested live on Horizon 26.1.2, 26.2 and 26.3: `.linear` files written, stats live, clean stops, no errors.
- The Horizon unit tests no longer build a real `JavaPlugin`, whose 26.1/26.2 constructor needs a running server. The test harness allocates the stub without calling any constructor.
