This release brings the Horizon plugin level with the forks. On the Folia and Canvas forks it replaces `v1.1.1` directly, with the same bytes on disk, config defaults and behavior. The Horizon plugin gets its first update since `v1.0.0` and now ships as a single jar for every supported Minecraft line.

## Breaking changes

- The Horizon asset was renamed from `linearmc-horizon-26.3-<proj>.jar` to `linearmc-horizon-1.0.0-1.1.2.jar`. The one jar loads on 26.1 through 26.3. Download scripts that use the old name need updating.

## Changes

- Four Horizon settings were read but never used. `flush-max-threads`, `flush-frequency` (the coordinator's age check; the heartbeat already followed the file), `compression-workers` and `long-distance-matching` now register the same core seams as on Canvas, with the documented defaults of 1, 10, 0 and 0.
- Horizon honors `crash-on-broken-symlink: false`, which boots without the symlink guard for forensic work. The default `true` still refuses broken symlinks. The flush-completion listener does nothing on Horizon, because the plugin has no event bridge.
- The plugin version follows the project tag. Tag builds stamp the Gradle project version, `paper-plugin.yml` and `horizon.plugin.json` with `LINEARMC_PROJECT_VERSION`; local builds keep `1.0.0-SNAPSHOT`.
- The jar is built against the oldest bundle (`26.1.2.build.74-stable`, `api-version: 26.1`). The six places where it touches NMS are identical in the 26.1 to 26.3 bundles, and it only uses API present in the oldest one, so one jar covers every Minecraft line.
- CI builds the plugin and runs its unit tests against every pinned bundle (26.1.2, 26.2, 26.3). The run includes a reflection patcher check that every mixin selector target exists in that bundle's NMS.
- Changes to commands, config keys or `linear$` seams must land on every server type in the same change (see `CONTRIBUTING.md`). Gate `4b` in `scripts/preflight.sh` checks the config keys and the seams.

## Fixes

- On Horizon, `flush-max-threads`, `compression-workers`, `long-distance-matching` and the `flush-frequency` age check ignored `config.yml`, so the coordinator and codec ran on the shipped defaults. They now read it.
- Horizon no longer ignores `crash-on-broken-symlink: false`.
- Horizon failed on live servers because hosts without the Moonrise bridge method rejected the whole mixin, and worlds stayed `.mca`. The redirect on the exists check now uses `require = 0`. The same jar ran live on Horizon 26.1.2, 26.2 and 26.3, wrote `.linear` files, reported live stats, stopped cleanly and logged no errors.
- The Horizon unit tests no longer build a real `JavaPlugin`, whose 26.1/26.2 constructor needs a running server. The test harness allocates the stub without calling any constructor.
