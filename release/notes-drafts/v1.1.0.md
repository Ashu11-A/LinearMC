LinearMC can now write three Linear layouts, and the reader accepts all of them. V1 is still the default; V2 and B_LINEAR can be chosen per world or for the whole server. This release also adds the V3 writer, recognizes Pumpkin files, speeds up the shutdown drain, adds Canvas 26.2 and 26.3 builds, and documents how to pick a version. Gameplay does not change.

## Added

- V2 bucketed writer. A region is split into an 8x8 grid of buckets by default (grid 1, 2, 4, 8, 16 or 32 can be chosen), each compressed and hashed on its own. Files keep the `.linear` extension, and busy worlds rewrite less data per save. V2 files can be read by DivineMC and the other way round.
- V3 writer, for advanced use: the DivineMC wire-4 bucketed format, with the same selection and conversion paths as V2.
- B_LINEAR buffered tier. Chunk writes go straight to a `.b_linear.swp` swap file and the master file is rebuilt at flush. It is meant for write-heavy worlds and adds an extra crash window. In steady state only the master is on disk: the swap is pruned on a clean close and staging files are swept on open.
- Pumpkin files use the same magic and extension as V1. LinearMC now tells them apart by structure, reads them and can convert them. Live Pumpkin files are never rewritten behind your back, and startup never converts them.
- Any-to-any conversion: `/linear convert --from mca|v1|v2|v3|blinear|pumpkin|linear|auto --to … [--grid …] [--execute]`, a dry run by default. A conversion in place validates the result before an atomic swap. If one coordinate has files in two formats, the job halts and keeps both.
- Writer selection per world (`region-format.linear.implementation: V1|V2|V3`, `grid-size`, `format: LINEAR|B_LINEAR|ANVIL`) or for the whole server (`-Dlinearmc.implementation=… -Dlinearmc.grid-size=… -Dlinearmc.format=…`). A valid flag overrides the config; an invalid value is logged and the default is used. The unknown-format warning now lists all three formats.
- Canvas 26.2 and 26.3 builds: `linearmc-canvas-26.2` and `linearmc-canvas-26.3` (26.3 is pinned to Canvas `main@cc4e7611`). The 47 overlay files the Canvas builds share now live in one common place, and each version keeps only its own adapters.
- The Horizon plugin drains dirty files on one daemon thread and forces a drain when it is disabled. Clean stops lose nothing, even on Minecraft lines where the storage flush and close paths never run.
- Documentation on choosing a version: a flag table and Versions section in the README, a selection guide in the operator notes, and a settings reference in `docs/configuration.md`.

## Fixed

- The shutdown drain flushed files one by one. It now flushes them in parallel and waits for all of them: 167 s became 51 s on 26.1.x and 35 s on the 26.3 test server. Vanilla and Anvil files behave exactly as before.
- Flush bookkeeping. A file that is still dirty after a flush (a write landed after the snapshot) is queued again instead of dropped. Every path in the core that changes data reports itself, so no write depends on the caller remembering to. A failed flush deletes its temp file and marks the file dirty again on every failure path, and `close()` keeps draining until the file is clean.
- The observability docs now quote the three-format warning exactly as the code prints it.
