LinearMC can now write three Linear layouts, and the reader accepts all of them. V1 is still the default, and V2 and B_LINEAR can be chosen per world or for the whole server. The release also adds a V3 writer, Pumpkin file detection, a faster shutdown drain, Canvas 26.2 and 26.3 builds, and docs on picking a version. Gameplay is unchanged.

## Added

- V2 bucketed writer. By default a region is split into an 8x8 grid of buckets (grid 1, 2, 4, 8, 16 or 32 can be chosen), and each bucket is compressed and hashed on its own. Files keep the `.linear` extension, and busy worlds rewrite less data per save. DivineMC reads V2 files, and LinearMC reads DivineMC's.
- V3 writer, for advanced use. It writes the DivineMC wire-4 bucketed format and uses the same selection and conversion paths as V2.
- B_LINEAR buffered tier. Chunk writes go straight to a `.b_linear.swp` swap file, and the master file is rebuilt at flush. It is meant for write-heavy worlds and adds an extra crash window. In steady state only the master is on disk: the swap is pruned on a clean close and staging files are swept on open.
- Pumpkin files use the same magic and extension as V1. LinearMC now tells them apart by structure, reads them and can convert them. It never rewrites a live Pumpkin file on its own, and startup never converts them.
- Any-to-any conversion with `/linear convert --from mca|v1|v2|v3|blinear|pumpkin|linear|auto --to … [--grid …] [--execute]`, which is a dry run by default. An in-place conversion validates the result before an atomic swap. If one coordinate has files in two formats, the job halts and keeps both.
- Writer selection per world (`region-format.linear.implementation: V1|V2|V3`, `grid-size`, `format: LINEAR|B_LINEAR|ANVIL`) or for the whole server (`-Dlinearmc.implementation=… -Dlinearmc.grid-size=… -Dlinearmc.format=…`). A valid flag overrides the config; an invalid value is logged and the default is used. The unknown-format warning now lists all three formats.
- Canvas 26.2 and 26.3 builds: `linearmc-canvas-26.2` and `linearmc-canvas-26.3` (26.3 is pinned to Canvas `main@cc4e7611`). The 47 overlay files the Canvas builds share now live in one common place, and each version keeps only its own adapters.
- The Horizon plugin drains dirty files on one daemon thread and forces a drain when it is disabled, so a clean stop loses nothing even on Minecraft lines where the storage flush and close paths never run.
- Docs on choosing a version: a flag table and Versions section in the README, a selection guide in the operator notes, and a settings reference in `docs/configuration.md`.

## Fixed

- The shutdown drain used to flush files one at a time. It now flushes them in parallel and waits for all of them, which took the drain from 167 s to 51 s on 26.1.x and to 35 s on the 26.3 test server. Vanilla and Anvil files behave as before.
- Flush bookkeeping. A file that is still dirty after a flush (a write landed after the snapshot) is queued again instead of dropped. Every core path that changes data reports the change itself, so no write depends on the caller remembering to. On every failure path a failed flush deletes its temp file and marks the file dirty again, and `close()` keeps draining until the file is clean.
- The observability docs now quote the three-format warning exactly as the code prints it.
