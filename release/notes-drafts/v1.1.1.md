This is a maintenance release that reorganizes the code. Coming from `v1.1.0`, replace the jar and you are done: no world conversion, and the bytes on disk, config defaults and runtime behavior are all the same. It is the first release that carries the Canvas 26.3 build (pinned to `main@cc4e7611`).

## Changes

- The converter was split up. `LinearRegionConverter` went from 3658 lines to a 596-line facade over `ConversionPipeline`, `CandidateScanner`, `ChunkCopier`, `ConversionValidator`, `ExplicitConvertRouter`, `ConversionCleanup` and `ConversionAlerts`. Each layout (V1, V2, V3, Pumpkin, Anvil, B_LINEAR) has its own module behind `AbstractVersionConvertModule`, with the same method names.
- The flush coordinator went from 1293 lines to a 598-line facade over `FlushSnapshotRegistry`, `ParallelFlushFanout` and `FlushLatencyWindow`. Snapshot-then-requeue, the barrier and the timing work as before.
- The buffered file went from 1123 lines to 972. Master and envelope logic moved to `BufferedMaster`, swap I/O to `BufferedSwapFile` and temp-file sweeping to `BufferedStagingSweep`. The rules for repair on open, drain on close and pruning did not change.
- `AbstractLinearVersion` and `AbstractBucketedVersion` hold the shared checks and the bucket flow, and V1, V2, V3 and Pumpkin implement the same hooks. `V2LinearBase` remains as a deprecated alias. Every version has its own public decoder and encoder classes, and LZ4 slot framing lives in `Lz4SlotCodec`.
- Choosing the container is now separate from choosing the version: `AbstractFormatSink` with `Linear`, `BLinear` and `Anvil` sinks. The probe helpers (factory, grid, names, storage probe, warmup) are grouped in `probe/`. V1 still ignores grid-size.
- Command classes are grouped into `queue/`, `stats/` and `parse/`.
- Build: staging for each server copies the whole core tree recursively. Deep subpackages used to be skipped, which broke the jar compile. The fork cache key now also hashes the staging actions, and the Horizon plugin imports point at the new packages.

## Fixes

- A buffered master can no longer be staged through the generic Linear render path. `BLinearFormatSink.createStaging` throws instead of producing a corrupt master; buffered staging stays on the owner path.
