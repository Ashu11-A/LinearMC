A server crash could leave a player file newer than the chunks around it, so an item put in a chest, or a shulker box placed, just before the crash could disappear. From this release a player file is written only after the chunks of the player's region are on disk. That ordering is on by default. `save-all flush` now waits for the disk before it reports success, and region and player files are replaced atomically.

Both forks also move to the latest upstream builds: Folia #28 and CanvasMC #1047.

## Data safety

- Players are saved after their chunks (`linear.coupled-save.enabled`, default on). Every 20 s each region saves its chunks and keeps its players' `.dat`, stats and advancements in memory. A background thread writes those files only after the chunk writes have reached the disk. Logout, `save-all` and plugin `saveData` calls use the same order. When a player leaves a region (teleport, portal, respawn), the region being left is saved first. If a chunk write fails, the player files wait and are retried; they are never written ahead of their chunks. A crash can now at worst duplicate an item moved just before it. It is not a transaction across regions (see `docs/limitations.md`).
- `save-all flush` waits for the disk on both forks and on Horizon on every host. It returns only after every queued chunk write and every running region flush is renamed and synced, then writes `<world>/linear-checkpoint/save-all.done`, which backup scripts can check.
- `save-off` has a time limit (`linear.save-off-max-duration`, default 120 s, 0 disables). A forgotten `save-off` turns saving back on with a warning to operators. Player files are not written during `save-off`.
- Player files are replaced with one atomic rename (`linear.durable-player-data`, default on), and `.dat_old` keeps the previous save.
- Region files: the folder is synced after each rename, so a power cut cannot undo it. A zero-length `.linear` file is moved to `.corrupt-<ms>` instead of being overwritten, and a region file that cannot be read is first copied to `<dimension>/linear-conflicts/`. `/linear stats` shows `quarantined=N` and `conflicts=N` when either is above 0.

## Validation

- Automated tests: core 478, Folia fork suite 149/149, CanvasMC fork suite 151/151, Horizon 65/65 on each dev bundle (26.1.2, 26.2, 26.3). The parity check passes in release mode with no gaps across 31 capabilities.
- Live `save-all` barrier and `save-off` limit checks on the Folia fork, the CanvasMC fork, and Horizon on Paper, Folia and CanvasMC 26.3: every `save-all flush` wrote its marker, with no region renamed after it.
- Live crash test on the CanvasMC fork with a real connected player and production save timings: five named shulker boxes, two moved into a chest, then the server process killed with `kill -9` 1 to 120 s later. With the new ordering off, 1 of 10 rounds came back out of sync (chest saved, player file not). With it on, 20 of 20 rounds came back intact. `kill -9` does not cut power to the host, so power loss is covered by the unit tests (directory sync, atomic rename), not by this live test.

## Upgrading

- Replace the jar. Worlds that are already Linear need nothing else.
- Backup scripts that keep `save-off` on for more than 120 s must raise `linear.save-off-max-duration` or set it to 0.
- The periodic player autosave is replaced by the region saves while `coupled-save` is on. To get the old behaviour, set `linear.coupled-save.enabled: false`.
- On Horizon on Paper, `save-all flush` can hold the tick for up to 20 s while it waits for the disk.
